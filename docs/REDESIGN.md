# finbot 重构设计文档 · 从"预测涨停"到"因子化前瞻收益排序"

> 状态：设计稿（待评审）。本文件只描述**目标架构与原理**，不含实现。
> 评审通过后再按第 14 节路线图分阶段写代码。

---

## 1. 为什么推倒重来

第一版把目标定为"预测当天哪些股票涨停"。从金融与经济学原理看，这个目标本身有结构性缺陷：

1. **挑战的是市场有效性里信噪比最差的一档。** 弱式有效市场假说（EMH）下，单凭历史价量难以稳定预测短期收益；而"当日涨停"是极端价格跳变，更难。
2. **反身性 / 前视问题。** 多数涨停由**当天才出现**的消息与资金驱动，这些信息不在事前特征里，模型无法学到真正的因果。
3. **标签病态。** 涨停每天约占全市场 1–2%，极度不平衡，且大量是"事后才知原因"。
4. **不可执行性（最致命）。** A股的 **T+1**、**封板即无流动性（一字板买不进）**、**手续费+滑点**，使得"即使预测准也未必能套现"。
5. **缺乏验证。** 没有回测就无法区分"有 edge"和"凑巧"。
6. **"套利"用词错误。** 这是承担风险的**投机性事件/动量交易**，不是无风险套利。

**结论**：把目标从"抓涨停事件"改为"估计横截面前瞻收益的相对排序"，并把系统价值重心从"选股 alpha"转向**风险管理 + 事件解读 + 可回测的纪律化流程**。

---

## 2. 设计原则（经济学根基）

- **P1 因子需有经济先验**：每个因子对应一个被实证/理论支持的收益来源（风险溢价或行为异象），而非技术指标堆叠。
- **P2 中性化**：剥离市值、行业、市场 beta 等共同暴露，追求相对 alpha 而非风险敞口收益。
- **P3 可执行性优先**：所有信号在 T+1、封板不可成交、交易成本约束下评估；多日持有以绕开封板流动性问题。
- **P4 一切可回测**：walk-forward、无前视、含摩擦；用 Rank IC / 分层收益度量 edge。
- **P5 风控是硬约束、且是主要价值源**：分散化与风险预算带来的稳定性比选股 alpha 更可靠。
- **P6 人机分工**：确定性计算交给 Python；定性判断（消息可信度、事件解读、regime、风控否决）交给 LLM Agent。
- **P7 诚实边界**：现实目标是**小而稳定的正 IC**（0.03–0.08 即良好），不是"挑出涨停"。所有输出带免责声明。

## 3. 新目标定义

**任务**：每个交易日，对可投资域内的股票，预测**未来 H 日的前瞻超额收益**并排序（learning-to-rank / 回归）。

- **持有期 H**：默认 5 与 10 个交易日两档（可配置）。多日持有规避封板不可成交问题。
- **标签 y**：`forward_excess_return = R_{t→t+H}(stock) - R_{t→t+H}(benchmark)`，基准用中证全指或所属行业指数。
- **预测产物**：横截面分数 → 排序 → 分层（Q1…Q5）。Top 分位作为多头候选。
- **评估指标**：Rank IC、ICIR、分层单调性、Top–Bottom 多空收益（仅作研究，A股做空受限）。

> 涨停榜不再是目标，降级为附属的"高风险投机观察池"（见第 12 节）。

## 4. 数据层：本地数据仓库（先做，收益最高）

**问题**：当前每天对每只股票现拉历史 K 线 → 几千次 HTTP，几十分钟，且无法回测。

**方案**：本地**增量数据仓库**，一次性下载、每日增量更新。

- **存储**：Parquet（按 `表/年` 分区）+ 一个 `meta.sqlite` 记录每张表的更新水位。路径 `data/warehouse/`（git 忽略）。
- **表（最小集）**：
  - `daily_bar`：日线 OHLCV + 复权因子（前复权）。
  - `daily_basic`：换手率、流通市值、PE/PB/PS、停复牌、是否 ST。
  - `index_bar`：基准与行业指数日线。
  - `money_flow`：主力净流入、北向资金（能拿到则入库）。
  - `news`：财经新闻（标题/时间/来源/原文链接）。
  - `events`：业绩预告/公告/分红/解禁等结构化事件。
  - `calendar`：交易日历。
- **接口**：`finbot.data.warehouse`
  - `update(asof)`：增量拉取并落盘（断点续传、限频退避、失败回退 mock）。
  - `bars(codes, start, end)` / `basics(...)` / `news(...)`：**统一从本地读**，毫秒级。
- **收益**：日常运行从"几十分钟"→秒级；并成为回测的前提。
- **数据源抽象**：沿用 `DataProvider` 子类思路（AkShare 现成、Tushare 可插拔），仓库层只面向 provider 接口。

## 5. 因子库（带经济先验 + 中性化）

每个因子写成 `_build_*`，登记到 `FACTOR_REGISTRY`，并标注【经济逻辑】【方向先验】【数据依赖】。横截面构建后统一做：**去极值(winsorize) → 标准化(z-score) → 行业&市值中性化(回归取残差)**。

| 类别 | 因子（示例） | 经济逻辑 | 方向先验 |
|---|---|---|---|
| 价值 | EP、BP、SP、股息率 | 估值均值回归 / 风险溢价 | 低估值→正 |
| 质量 | ROE、毛利率、应计、资产周转 | 优质企业长期跑赢；应计异象 | 高质量→正 |
| 动量 | 20/60/120 日动量（剔除最近5日） | 中期动量延续（行为：反应不足） | 正 |
| 反转 | 最近 5 日反转 | A股散户主导短期反转 | 负 |
| 低波动 | 60 日波动率、特质波动 | 低波动异象（彩票偏好致高波高估） | 低波→正 |
| 流动性 | 换手率、Amihud 非流动性 | 流动性溢价 / 散户过度交易 | 视方向 |
| 规模 | 流通市值 | 小盘溢价（需中性化掉，避免纯吃 beta） | 中性化对象 |
| 资金流 | 主力净流入、北向净买入 | 信息优势资金（聪明钱） | 正 |
| 情绪 | 板块新闻数/情绪、涨停家数 | 情绪扩散与短期动量 | 正、但易反转 |
| 事件漂移 | 盈余公告后漂移(PEAD)、调研热度 | 市场对新信息反应不足 | 正 |

> 关键：**规模/行业/beta 作为中性化对象**，不直接当 alpha 因子，避免"以为是 alpha、其实在吃风险溢价"。

## 6. 标签与样本构建

- 对每个 `(date, code)`：用仓库的复权价计算 `R_{t→t+H}`，减基准得超额收益作为 `y`。
- **样本过滤**：剔除停牌、上市<N日、当日触及涨跌停（无法建仓）、ST、流动性不足。
- **关键：避免前视**——特征只用 `≤ t` 的信息；标签用 `t+1 → t+1+H`（T+1 起算）。
- 产出带标签的**面板数据集** `data/datasets/panel_<H>.parquet`，供训练与回测共用。

---

## 7. 模型层

- **基线**：LightGBM `lambdarank`（learning-to-rank）或回归 + 横截面排序。
- **输入**：第 5 节中性化后的因子矩阵；**按日做横截面标准化**。
- **训练**：滚动窗口（如近 2–3 年训练，预测下一段），定期再训练。
- **可解释**：输出每只票的 Top 驱动因子（SHAP / 增益），供 Agent 解读。
- **回退**：无训练模型时，用**因子等权合成**（IC 加权更佳）的透明打分，开箱即用。
- 产物：`models_store/rank_<H>_<train_end>.txt` + 训练元信息（IC 曲线、特征重要性）。

---

## 8. 验证与回测框架（必做）

**这是判断"有没有 edge"的唯一手段，不可省。**

- **Walk-forward**：训练窗→样本外预测窗，向前滚动；严禁用未来数据。
- **因子层评估**：逐日 Rank IC、ICIR、因子衰减、分层(Q1–Q5)收益单调性、换手率。
- **策略层回测，含 A股摩擦**：
  - **T+1**（次日开盘成交）、
  - **涨跌停不可成交**（开盘即涨停的票当日不可买/不可卖）、
  - **停牌跳过**、
  - **手续费+印花税+滑点**（可配置，默认双边 ~0.13%+冲击）。
  - 组合按第 9 节规则定期再平衡。
- **报告**：年化、波动、夏普、最大回撤、胜率、换手、与基准对比、分年/分regime表现。
- 接口：`finbot.backtest`（`run_backtest(start, end, H, cost_model, rebalance)`）。

## 9. 组合构建与风险模型

替换当前"按分数线性定仓"，引入风险意识：

- **风险模型**：行业因子 + 统计因子的协方差估计（先用简化版：行业哑变量 + 收缩协方差 Ledoit-Wolf）。
- **构建**：在预期收益（模型分）下做**带约束优化**——
  - 单票上限、行业暴露上限、对市值/beta 中性、目标波动或目标 N 只等权，
  - 总敞口与现金缓冲（沿用现有风控硬约束）。
- **再平衡**：按 H 周期或触发式；控制换手以省成本。
- 落到实盘：与用户 `portfolio.json` 对齐，输出**调仓指令**（买/卖/调整到目标权重）而非孤立买点。

---

## 10. 市场状态（regime）叠加

- 用大盘宽度（涨跌家数、新高新低）、波动率（如中证波动）、流动性、北向方向判定 regime：`risk-on / 中性 / risk-off`。
- **作用**：动态调节策略总敞口与因子权重（趋势市重动量、震荡市重反转/低波），规避"动量崩溃"。
- 这是 `market-analyst` Agent 的定量输入 + 定性研判结合点。

---

## 11. Agent / Skill 在新架构中的职责（人机分工）

- **market-analyst**：消费 regime 指标 + 新闻 → 市场环境画像、主线板块、敞口建议。**新增真实价值**：定性解读消息可信度、政策含义。
- **stock-picker**：在**模型排序榜 + 因子归因 + 事件催化**上做研判，剔除"有分无逻辑"，输出观察清单。
- **strategy-advisor**：消费**组合优化器的调仓建议** + 用户实仓 → 风控优先的操作计划，可否决。
- **新增 Skill**：`update-data`（更新数据仓库）、`run-backtest`（回测并解读报告）、`build-dataset`（构建带标签面板）。
- 既有 Skill 改为对接新 CLI 子命令。

## 14. 分阶段实施路线图

> 每个里程碑独立可用、可验证；建议按序，但 M1 必须先行。

- **M1 数据仓库 + 提速**：`warehouse.py`、`update-data` skill、CLI `finbot update`。验证：二次运行秒级、本地能取数。
- **M2 标签与面板**：`labels.py`、`build-dataset`，产出 `panel_5/10`。验证：无前视、样本统计合理。
- **M3 因子库重构 + 中性化**：`registry.py`、重写因子、单因子 Rank IC 体检。验证：核心因子 IC 符号与先验一致。
- **M4 回测框架**：`backtest/`，含 T+1/封板/成本。验证：基线（如等权动量）回测结果可信、可复现。
- **M5 排序模型**：`ranker.py`，walk-forward 训练，IC/分层报告。验证：样本外 IC、分层单调。
- **M6 组合与风险**：`portfolio/`，带约束构建 + 调仓指令。验证：回测换手/回撤改善。
- **M7 regime + Agent 重接**：`regime.py`、三 Agent 与新 Skill 对齐。验证：端到端简报。
- **M8 涨停榜降级**：`speculate.py`，明确风险标注。
- **M9 清理**：移除旧 `limitup.py`/旧策略，更新 README/CLAUDE.md/测试。

## 15. 风险、局限与诚实边界

- **没有圣杯**：即便重构，现实目标是**小而稳定的正 IC + 良好风控**，不保证收益、更不预测涨停。
- **数据质量**：AkShare 免费接口有限频、字段漂移、历史不全；财务数据有披露滞后（须按公告日对齐，防前视）。
- **非平稳与过拟合**：市场 regime 漂移；因子会拥挤失效。靠 walk-forward + 朴素模型 + 滚动再训练缓解，不能根除。
- **可执行性**：回测含摩擦但仍乐观于真实滑点/排队；实盘前需小资金验证。
- **合规**：仅供研究学习，不构成投资建议；遵守证券法规，风险自负。
